# 백업 및 복구
**Storage > Veritas Backup > 콘솔 사용 가이드 > 백업 및 복구**<br>
이 문서는 Veritas Backup 서비스를 활성화하고, 활성화 이후 콘솔에서 백업 에이전트 설치·백업·복구 기능을 활용하는 방법을 안내합니다.
먼저 [프로젝트 서비스 활성화 가이드](https://docs.nhncloud.com/ko/nhncloud/ko/console-guide/#_21)를 참고해 Veritas Backup 서비스를 활성화하세요.

조직과 프로젝트를 선택한 뒤 NHN Cloud 콘솔 GNB(Global Navigation Bar)의 **Storage > Veritas Backup** 메뉴로 이동하면 에이전트, 백업, 복구, 리포트 네 가지 기능을 사용할 수 있습니다. 리포트 메뉴에서는 모든 백업 및 복구 리포트를 한눈에 조회하고 다운로드할 수 있습니다.


## 백업 에이전트 설치

백업 및 복구 기능을 사용하려면 먼저 에이전트를 설치해야 합니다. 설치할 서버 정보를 입력하고 신청하면 해당 환경에 맞는 에이전트 설치 파일을 제공합니다. 설치 파일을 서버에 설치하면, 시스템이 자동으로 에이전트 설치 신청을 처리합니다. 이용 중인 백업·복구 서비스가 모두 중지된 경우에만 에이전트 신청 이력을 삭제할 수 있습니다. 에이전트의 상태값은 **설치 접수 → 설치 확인 → 설치 완료** 순으로 변경되며, 설치를 취소하면 해당 신청서는 목록에 더 이상 표시되지 않습니다.
1. NHN Cloud 콘솔에서 **Storage > Veritas Backup**을 선택합니다.
2. **에이전트** 탭에서 **에이전트 설치**를 클릭합니다.
3. **에이전트 설치** 화면에서 필요한 정보를 입력하고 **신청**을 클릭합니다.

  * **대상 유형**: NHN Cloud 인스턴스는 `인스턴스`, 외부 VM 또는 비(非)인스턴스 서버는 `그 외`를 선택합니다. 대상 유형에 따라 에이전트를 설치할 서버를 지정하거나 서버 정보를 직접 입력합니다.
    * **인스턴스 선택 시**: 현재 프로젝트에서 에이전트가 설치되지 않은 인스턴스만 목록에 표시되며, 설치할 서버를 지정합니다.
    * **그 외 선택 시**: 서버명, 호스트네임, IP, OS 유형을 직접 입력합니다.
  * **서버**: `인스턴스` 대상이라면 에이전트를 설치할 서버를 지정하고, `그 외` 대상이라면 서버명을 직접 입력합니다.
  * **호스트네임**: 1~63자까지 입력할 수 있으며, 영어 소문자(a-z), 숫자(0-9), 하이픈(-)만 사용할 수 있습니다.
  * **신청명**: 50자 이내로 에이전트 신청 건을 구분할 수 있는 이름을 입력합니다.
  * **연결된 IP**: `인스턴스`를 대상이라면 서버의 IP가 자동으로 표시되며 백업 대역 IP인지 확인합니다. `그 외` 대상이라면 백업 대역 IP를 정확하게 기입해야 합니다. 
  * **IP 입력**: 에이전트 설치에 사용할 IP 정보를 입력합니다.
  * **OS 유형**: `인스턴스` 대상이라면 서버의 OS 정보가 자동으로 채워지고, `그 외` 대상이라면 Linux 또는 Windows 중에서 선택합니다.

4. 에이전트 신청 목록에서 해당 신청 건을 클릭하면 **설치 정보** 모달이 열립니다.
5. **에이전트 설치** 행의 **설치파일 다운로드**를 눌러 파일을 내려받고 압축을 해제한 뒤 설치를 진행합니다. 설치가 끝나면 통신 확인을 위한 설치 검증을 수행해야 하며, 검증이 완료되어야만 백업 서비스를 신청할 수 있습니다.

* **에이전트 설치 파일**은 신청 시 선택한 OS 유형에 따라 Linux 또는 Windows 전용 파일이 제공됩니다.
* **이용중인 항목**에서는 해당 서버 정보를 기반으로 수행한 백업·복구 신청 이력을 최신 완료 작업 순으로 확인할 수 있습니다.
* **이력 조회**에서는 설치 대기, 설치 접수, 설치 완료 순으로 최신 상태가 정렬되며, 삭제된 에이전트는 표시되지 않습니다. 이용 중인 백업이 있으면 에이전트를 삭제할 수 없습니다.
* **상태별 액션**
  * 설치 접수: [닫기], [삭제] 버튼이 노출되며, 설치 파일을 다운로드할 수 있습니다.
  * 설치 확인: [삭제] 버튼만 노출되며, 설치 파일 다운로드 및 수동 설치 검증이 가능합니다. 수정이 필요하면 신청서를 삭제 후 해당 신청서 내용을 기반으로 다시 신청해야 합니다.
  * 설치 완료: [백업 신청] 버튼이 활성화되며, 클릭하면 서버 정보가 백업 신청 페이지에 자동으로 채워집니다.
  * 서버 자원이 백업 대역 IP로 설정되고 직접 설치를 완료했다면 설치 검증도 자동으로 수행됩니다.
* **에이전트 제거 유의사항**: 에이전트 신청 이력을 삭제해도 설치된 에이전트가 자동으로 제거되지는 않으므로 필요 시 직접 프로그램을 삭제해야 합니다.


## 백업 신청

에이전트 설치와 검증이 끝난 서버만 백업을 신청할 수 있으며, 작업이 완료되면 상세 모달 창에서 작업이 완료된 백업 신청의 상세정보를 확인할 수 있습니다. 리포트를 발행한 뒤 DB 유형 스케줄을 변경하면 이전 스케줄과 리포트 이력은 **스케줄 이력** 탭에서 제공됩니다. 백업 리포트가 존재하는 신청 건은 삭제할 수 없고, 중지 처리만 가능합니다.

백업 목록에는 기본 7가지 상태값(**신청 요청, 요청 접수, 작업중, 생성 완료, 중지 요청, 중지 접수, 중지 완료**)이 표시됩니다.
* 파일 백업(셀프 서비스): **신청 요청, 요청 접수, 생성 완료, 중지 요청, 중지 완료, 삭제**
* DB 백업(매니지드 서비스): **신청 요청, 요청 접수, 작업중, 생성 완료, 중지 요청, 중지 접수, 중지 완료**

삭제 버튼은 리포트 이력이 없는 신청 건이면서 상태가 **신청 요청**, **요청 접수**, 또는 리포트가 없는 **중지 완료**일 때만 노출됩니다. 생성 완료 상태의 백업 신청은 리포트 이력이 만들어지고 중지가 선행되어야 하므로 즉시 삭제할 수 없습니다. 리포트 이력이 하나라도 존재하면 삭제가 불가능합니다.

에이전트 상태가 **설치 완료**인 서버가 있어야 **백업 신청** 페이지로 이동할 수 있습니다.

1. NHN Cloud 콘솔에서 **Storage > Veritas Backup**을 선택합니다.
2. **백업** 탭의 **백업 신청**을 클릭합니다.
3. **신청 정보**, **스케줄**, **담당자 정보 및 요청사항**을 입력한 뒤 **신청**을 클릭합니다.

* **신청 정보**
  * **서버**: 에이전트 상태가 **설치 완료**인 서버만 선택할 수 있습니다.
  * **신청명**: 50자 이내로 백업 신청 건을 구분할 수 있는 이름을 입력합니다.
  * **유형**: 셀프 서비스 기준으로 파일 백업을 제공하며, 경로 입력 후 **추가** 버튼으로 최대 100개까지 등록할 수 있습니다. 등록된 경로는 삭제만 가능하고 수정은 지원하지 않습니다.
* **스케줄**
  * 첫 번째 행은 풀 백업(Full)만 설정할 수 있고, 두 번째 행부터는 풀/증분(Incremental) 중 하나를 선택합니다.
  * 데이터 보관 기간은 기본 2주이며 1개월도 선택할 수 있습니다.
  * 스케줄 유형, 스케줄명, 백업 주기, 시작 시간, 작업 시간을 지정합니다.
  * **스케줄 템플릿** 버튼으로 자주 사용하는 스케줄을 저장·호출할 수 있으며, 프로젝트당 최대 100개까지 생성할 수 있습니다.
* **담당자 정보 및 요청사항**
  * **담당자**: 신청자를 제외하고 최대 2명까지 지정할 수 있으며, 필요 시 해당 담당자에게 별도 연락이 진행됩니다.
  * **요청사항**: 추가로 전달할 내용을 자유 형식으로 입력합니다.

> !!! tip "알아두기"  
>  * 설정한 백업 시작일이 신청일보다 과거면 다음 주차 스케줄부터 실행됩니다. 예를 들어 금요일에 `주 단위-화요일` 스케줄을 신청하면 다음 주 화요일부터 백업이 시작됩니다.  
>  * 동일 프로젝트에서 기존 백업 신청 이력이 있다면 스케줄 템플릿을 통해 스케줄을 불러오거나, 사용하지 않는 템플릿을 모달에서 삭제할 수 있습니다. 템플릿을 삭제해도 해당 템플릿을 사용 중인 스케줄에는 영향이 없습니다.  
>  * 파일 유형은 백업 상세 페이지에서 언제든 스케줄을 수정할 수 있지만, DB 유형은 담당자와 협의하거나 상태가 `신청 요청` 또는 `생성 완료`일 때만 스케줄 수정이 가능합니다.  
>  * 선택한 데이터 용량에 따라 추가 요금이 발생할 수 있습니다.  
>  * DB 유형의 백업 스케줄을 수정하면 기존 스케줄 정보와 리포트는 스케줄 이력 탭에서 계속 확인할 수 있습니다.

* **백업 상세 및 수정**
  * **리포트** 버튼: 백업 리포트 상세 페이지에서 작업 결과를 확인합니다.
  * **스케줄 이력** 버튼(DB 유형): 이전 스케줄 정보와 리포트 이력을 확인합니다.
  * **파일 유형**
    * 상태에 관계 없이 [수정] 버튼을 통해 신청 정보를 다시 입력할 수 있습니다. 단, 서버 및 백업 유형은 수정할 수 없습니다.
    * 상태가 `생성 완료`이면 서버·유형은 수정할 수 없습니다.
  * **DB 유형**
    * 상태가 `신청요청`이면 [수정] 버튼을 통해 신청 정보를 다시 입력할 수 있습니다. 단, 서버 및 백업 유형은 수정할 수 없습니다.
    * 상태가 `생성 완료`이면 [스케줄 수정] 버튼으로 스케줄만 변경할 수 있으며, 서버·신청명·유형은 수정할 수 없습니다.

## 복구 신청
Veritas Backup에서 생성된 백업 이력이 있을 때만 복구를 요청할 수 있습니다. 파일 복구는 셀프 서비스 방식으로 신청 즉시 작업이 시작되며, 결과는 콘솔 리포트에서 바로 확인할 수 있습니다. DB 복구는 매니지드 서비스이므로 운영 담당자가 신청서를 확인한 뒤 연락을 통해 세부 일정을 조율하고 수동 절차로 복구를 진행합니다. DB 복구는 업무 시간(오전 10시~오후 6시) 이후 접수하면 익일 영업일에 처리될 수 있습니다.

복구 목록에는 복구 유형에 따라 서로 다른 상태값이 노출됩니다. 이용 중인 백업이 존재해야만 복구 신청 페이지로 이동할 수 있습니다.
* 파일 복구(셀프 서비스): `신청 요청`(사용자가 신청한 직후), `작업중`(즉시 복구 실행), `성공/실패`(작업 결과)
* DB 복구(매니지드 서비스): `신청 요청`(사용자 신청), `요청 접수`(담당자 확인), `작업중`(수동 복구 진행), `생성 완료`(복구 완료), `중지 요청/중지 접수/중지 완료`(작업 취소 흐름)

1. NHN Cloud 콘솔에서 **Storage > Veritas Backup**을 선택합니다.
2. **복구** 탭에서 **복구 신청**을 클릭합니다.
3. **소스 설정**, **타깃 설정**, **담당자 정보 및 요청사항**을 입력하고 **신청**을 클릭합니다. 파일 복구는 신청과 동시에 작업이 시작되며, DB 복구는 운영 담당자의 연락 이후 확정된 일정에 맞춰 진행됩니다.

* 소스 설정
  * **소스 서버**: 복구할 소스 서버를 선택할 수 있으며 백업 이력이 존재하고 데이터 보존 기간이 유효하며 에이전트 상태가 설치 완료인 서버만 목록에 표시됩니다.
  * **신청명**: 50자 이내로 복구 신청 건을 구분할 수 있는 이름을 입력합니다..
  * **복구 상세 설정**: 백업 신청명, 유형, 백업 일시, 용량을 기준으로 복구 대상 시점을 선택하는 팝업입니다. 만료일 기준 최신순으로 정렬되어 노출되며 단일 선택만 가능합니다.

* 타깃 설정
  * **프로젝트/타깃 서버**: 기본값은 소스 서버와 동일하며, 체크를 해제하면 동일한 프로젝트 내에서 에이전트가 설치된 다른 서버로 변경할 수 있습니다. 소스와 타깃은 반드시 동일한 프로젝트에 속해야 합니다.
  * **타깃 경로**: 기본값은 소스 경로이며 자유롭게 수정 가능합니다. 입력된 경로가 실제 타깃 서버에 존재하는지는 별도로 검증하지 않습니다. **경로 초기화** 버튼을 클릭하면 모든 경로가 최초 설정된 소스 경로와 동일하게 변경됩니다.
  * **희망 작업기간**(DB 복구 전용): 매니지드 복구 시 원하는 작업 기간을 입력할 수 있으며 실제 일정과는 차이가 있을 수 있습니다. 

* 담당자 정보 및 요청사항
  * **담당자**: 복구 담당자를 선택할 수 있습니다. 담당자는 신청자 본인을 제외하고 최대 2명까지 추가할 수 있으며, 요청한 서비스를 원활하게 수행하기 위해 지정된 담당자의 연락처로 별도 연락을 진행합니다.
  * **요청사항**: 복구에 필요한 요청이 있다면 자유롭게 입력하여 요청할 수 있습니다. 

## 리포트

* 공통 : 구분, 신청명, 상태, 유형, 실행일, 보관만료일, 데이터 보관 기간, 용량, 평균 속도, 파일 개수, 작업 시작/종료 일시, 소요시간 등의 항목을 제공합니다. 용량과 속도는 KB 단위로 전달된 데이터를 GB/TB 등으로 변환해 소수점 첫째 자리까지 표기하며 둘째 자리부터는 반올림 처리합니다. 파일 개수는 백업/복구된 파일 수 뒤에 `files`를 붙여 표기합니다. (예: 2 files)
* **전체 리포트 목록**: 백업 및 복구 리포트 전반을 확인할 수 있습니다. 유형(백업/복구), 상태값(전체/성공/실패), 실행일 기간(기본값: 최근 3개월)으로 검색 및 필터링할 수 있으며, 검색 결과 목록을 엑셀 파일로 다운로드할 수 있습니다.
* **백업 상세 리포트 목록**: 상태는 성공 시 `성공`, 실패 시 `실패` 형식으로 노출됩니다.
* **복구 상세 리포트 목록**: 복구 유형은 텍스트로 `일반 복구`가 노출됩니다.

## 에이전트 제거
에이전트 제거 시 이용 중인 백업이 진행되지 않거나 오류가 발생할 수 있으므로 반드시 해당 서버에 대한 백업 스케줄을 모두 중지 한 뒤 에이전트를 제거해야 합니다. 에이전트 신청 이력을 삭제하더라도 설치된 백업 에이전트는 자동으로 제거되지 않으므로 사용자가 직접 프로그램을 삭제해야 합니다.
